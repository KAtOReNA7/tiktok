# 三只不服｜口播评审与复盘调优系统

系统标识：SCRIPT_REVIEW_LOOP。现行版本：1.1。确认日期：2026-10-08（Asia/Shanghai）。
状态：用户已确认核心闭环与本账号阶段性经验线；评分锚点、参照池、经验线和校准方法均为可迭代试行规则。
本文件属于策划与运营系统的长期说明，不是Codex单集制作指令，不纳入PRD，不修改制作模板、素材交付或已锁稿。
版本决策与原因见 [迭代记录](operations_script_review_history.md)；运营入口见 [运营接续](operations_handoff.md)。

本次升级的是评审与诊断协议。编辑评分ES1.0、参照池RS1.0及第7节实测算式保持不变；不得因为经验线加入就无验证改变百分制权重，或把运营经验线解释成平台算法率。新稿叙事与制作的执行检查单独按现行PRD及spec/narrative_retention.json执行。

## 1. 固定目标与闭环

每次提供新选题的完整口播稿，必须同时交付上线前百分制评审。用户采用的最终稿在上线前冻结评分、预判和写作版本；上线后接入真实观看数据评分；复盘检查预判兑现与偏差；提出并验证写作改法；依据新作品的验证结果自动调优，保留每次迭代的文字记录。

固定流程：
提供口播及预评 → 定稿冻结 → 核对实际发布版本 → 采集同龄期数据 → 上线后评分 → 诊断偏差 → 小范围试验 → 验证、采用或回滚 → 更新规则与迭代记录。

系统必须同时保存“写的时候为什么认为可行”和“观众实际如何观看”。不只做选题与评论复盘，也不只看文案是否通顺完整。

## 2. 三类评价各自回答什么

| 评价 | 百分制/呈现 | 用途 |
| --- | --- | --- |
| 上线前编辑评分 | 0—100分，分项与原句依据一并展示 | 评价本稿按当前写作标准完成得怎样，指出可检验的具体弱点 |
| 上线后开场留人分 | 0—100分，同参照池2秒跳出率的反向相对位置 | 评价成片开场实际留人表现 |
| 上线后全程留人分 | 0—100分，同参照池完播率的相对位置 | 评价成片整体观看表现 |
| 事实与论证风险 | 独立文字标签、依据与处置 | 检查来源、关键前因、人物归责与结论范围 |

口播评审及其留人评分不再用S/A/B/C/D。既有S/A/B/C/D运营等级可并行用于作品运营表现；须明确其现行定义、窗口和用途，不能替代本系统百分制，也不将经验线直接转换成固定等级。运营成绩、口播编辑判断和开场/全程实测分别展示。

上线前编辑分与上线后相对位置分含义不同，不直接相减，不合成一个总分，不把95分称为95%留存或95%爆款概率。事实风险不通过扣留人分抹去真实观看成绩；确有事实错误仍须记录并处理。

## 3. 上线前百分制：初始规则ES1.0

每篇新稿按下面五项分别评0／5／10／15／20分，合计100分。各项等权是本版的工作约定，尚未证明是最佳权重，后续通过新作校准；不得宣称由平台算法推导。

| 项目，满分20 | 必须检查的问题 |
| --- | --- |
| 开头兴趣与冲突 | 首句是否立即给出具体人物、动作及反常关系？冲突是否值得目标观众继续了解，而不只是语法清楚？ |
| 单遍理解成本 | 谁做什么、谁获益、谁付代价是否清楚？陌生人名、官职、地名、制度是否产生不必要的学习负担？ |
| 正文兑现与推进 | 标题和首句的承诺是否兑现？下一句是否回应刚产生的问题，提供有用的新动作、解释或后果，而非塞事实或重述判词？ |
| 情绪交付与账号风格 | 反差、讽刺或认可是否落在具体关系上？是否符合三只不服的唱反调风格、自然口语和必要人物责任边界？不把攻击越强当分越高。 |
| 结尾收束 | 是否把本篇的代价、关系或认可说到位？有效呼应、责任追问、重复强调均可；不强制最后反转或再添新事实。 |

统一锚点：
- 0：该项缺失或明显妨碍本稿成立。
- 5：问题突出，需多次解释、承诺明显不足或交付很弱。
- 10：基本成立，但主要依靠常规讲述，或存在可引用的明显弱点。
- 15：整体扎实，局部仍有改进空间。
- 20：本项有明确可复用价值，能举出本稿原句及匹配的学习样本；仍属编辑判断，未经本稿观众验证。

每项必须给出一处原句、具体理由和必要的反例/疑点。不允许只给“信息密度高”“很有冲突”等套话。若大量稿件都满分，要检查评价是否只验证形式，而没有检验观众兴趣与理解成本；不得为了制造差异随意降分。

新稿评审随口播一起提供，独立于纯口播正文；不把评分、说明或时码混入voice_script。评分低不自动触发生图、改写已锁稿或要求用户逐项确认。

## 4. 上线前必须冻结的预判

每篇至少记录：
1. 作品内部键、口播稿版本、写作系统版本、评分规则版本、评分时间、评审者。
2. 总分及五项分数、原句依据、最强优点与最可能失败的一项。
3. 首句具体承诺；观众接下来应产生的问题；正文在哪句话兑现。
4. 预计最容易流失的原句/段落，以及相应的验证指标和替代解释。
5. 对开场和全程表现的方向预判、使用的已发布学习样本及其可比性。
6. 计划时长、标题版本、模板/声音计划、事实风险；计划与实际分开。

初期方向预判标为“未经校准的编辑预判”，可以写预期优于/接近/弱于明确参照，不能假装已经掌握可靠留存率。只有建立并验证从编辑特征到实际相对位置的校准映射后，才给“预期开场/全程实测分区间”；必须注明预测映射版本、参照池、范围与信心。

用户改稿或更换首句后新增评审版本，再冻结最终采用稿；保留原记录，不覆盖。上线后的回溯补评分明确标“回溯审议”，不可冒充当时的预测。没有真正上线前记录的旧作不用于验证事前预测准确性。

## 5. 发布版本核对

作品发布后，以真实作品ID连接文案记录与后台快照。核对实际标题、口播、字幕、时长、模板和声音是否与冻结记录一致，记录已核验范围；未逐字听审不得写“成片全文已认证”。

每次作品对照分别标明口播与制作证据来源及核验范围：
- 实际发布成片：可检验已看到的画面、字幕、声音及顺序；只看截图不得声称已核完整音轨。
- 最终音频逐字转录：可检验真实口播原句；没有对应成片，不能据此判定首图、字幕可读性或转场实际执行。
- 最终采用的制作源稿：可评原句结构与计划，但未对照成片前不得写成实际播放内容，也不归因到具体秒点。
- 候选稿、旧版本或来源不明文本：只作待核线索，不冒充采用稿。

同一作品可以同时有多种证据，分别记录核过什么、缺什么；高等级材料不自动证明其他维度已核验。无法取得成片时继续做有来源的源稿分析，明确证据限制，不虚构制作缺陷。

若实际稿件或制作发生变化，新增“执行偏差”记录，保留原预判；不能把预判失败直接归于原文案。没有实际音频，不用字数伪造某句起止秒数。

仅公开且已发布的本系列作品进入活动运营评分。隐藏、私密、草稿、未发布定时作品单列状态；有真实异常/处罚记录的观察单列，不直接用于默认规则升级。异常不等于文字质量低。

## 6. 上线后采集窗口与参照池RS1.0

沿用现有每日复盘节奏，不为本文件新建重复定时任务。主观察采用实际发布龄期[24,48)小时、[72,96)小时内最早取得的累计快照，另可在至少7天时观察成熟表现。目标24/72小时、实际采集时间和真实龄期分别记录；一次每日采集不声称精准卡在第24/72小时。名称用“24—48小时观察分”“72—96小时观察分”；窗口内部年龄差仍存在，差异较大时注明有限可比，不能挑选表现最好的一次快照。错过窗口明确标“迟到观察”及实际龄期，不补写成准点快照，不以一次晚采的累计量作为24小时终局。发布不足24小时只列首轮观察，不下成熟成败结论。

每个参照池记录benchmark_id、冻结时间、成员作品ID、指标快照、时长范围、观察窗口、数据来源、纳入/排除条件和有效样本量。优先同龄期及相近时长；初始可按21—25／26—30／31—35／36—40秒分组，组不足时不偷偷合并，更宽分组只能单列为临时参考并解释代价。

默认每项需至少10个可用参照作品后才给相对位置分；这是展示试行分数的操作下限，不是统计可靠性保证，分数旁同时显示有效N和试行标识。N=10时一条参照就可能改变约10分，小分差不能直接解释为真实质量差异。小池、极早期或低曝光观察标“暂估/不足以评分”，原始比率仍可展示；没有足够数据则不强行出分。被评作品不作为自身参照成员。

同一作品的前后验证使用预先指定或已冻结的参照池；更新参照池需新版本，同时保留旧分。池变化不能说成作品自身改善。当前累计快照的回顾分、同龄期观察分、成熟分分开，不混成一列排名。

## 7. 上线后百分制的计算和边界

设某项有N个有效参照作品（不含被评作品）。使用未经显示取整的原始比率；如只有平台显示精度，注明这一限制。

- 开场留人分 = 100 ×（参照中2秒跳出率高于本作的个数 + 0.5 × 与本作相等的个数）÷ N。
- 全程留人分 = 100 ×（参照中完播率低于本作的个数 + 0.5 × 与本作相等的个数）÷ N。

计算保留未取整值，用户主表显示整数，两项原始百分比同时展示。这是组内经验相对位置，不是行业合格线、文案因果分、观看概率或平台官方评分。

两项暂不加权为总分。取得5秒留存、平均观看时长/观看占比和逐秒曲线后，将它们用于对应阶段诊断；如要改变评分构成，先记新版本、理由和验证计划，不把新指标静默塞进旧算式。

不同观察窗口、时长组、参照池版本的分数不能直接比较。同一实验沿用同一冻结基准，后台相同显示值按并列处理，不能把读取误差当差异。

零播放与未采集分开：真实零播放保留为0；未取得标缺失；零播放没有有效观看率，不以平台占位0%给留人分。有真实观看的0%完播则是有效观察，不能因成绩低排除。

缺失字段标缺失，不填0，不用2秒替代5秒，不把当天跳出拼到历史完播，不凭播放次数推算未核实的有效观看分母。播放、分享、关注和评论需求单独呈现，留人分不承担全部运营价值评价。高留人低播放也不能自动判作文案失败。

### 7.1 本账号阶段性经验线（2026-10-08起试行）

以下用于本账号20—40秒作品的诊断与新稿试验，不是抖音官方设定、流量保证或评分算式。后台“完播率”按字段原名记录，不笼统改称5秒或任意时间点“留存率”。

| 指标 | 阶段性用途 |
| --- | --- |
| 完播率<20% | 整体观看风险区：排查承诺兑现、后半新事实、理解成本与执行偏差 |
| 完播率≥20% | 越过当前风险底线，仍需检查是否持续提供观看收益；不称爆款达标 |
| 2秒跳出率≤30% | 当前开场优化目标；仍需检验正文和后续传播，不保证起量 |
| 2秒跳出率>30%且≤40% | 开场优化区：排查选题识别、首句、首图与字幕共同造成的理解成本 |
| 2秒跳出率>40% | 开场高风险区：优先核对上述实际执行和兴趣承诺，不直接归因于文案 |

经验线只对当次公开、已发布、20—40秒、来源清楚且未见真实推荐异常的可比作品试用。正常推荐需有可核记录或注明“未见已知异常”，不能以低播放反推限流，也不能凭公开状态保证没有异常。非该时长单列；异常观察单列；发布不足24小时保留提示但不进入成熟成败对照。正式评价优先按第6节同龄期窗口、相近时长和流量性质比较；无法匹配则标回顾性或有限可比，不把“至少24小时”视为完全同龄。

每日滚动复算三档跳出和两档完播的交叉分组，保留有效N、纳入/排除依据、龄期与时长差、播放分布、分享/关注及缺项。某格N=0或很小要明示，不推断没有例外。平台“万”显示值保留约数，不当精确播放值，不用其差值声称精确新增播放。

同时保留“越线仍起量”和“两项较好但未起量”等反例。相关分界支持运营排查，不证明推荐的因果开关；截至本版，早期观看表现能否预测后续新增推荐仍待独立新作与后续快照验证。高流量组出现更高完播，可作为观察，不临时加一条未经验证的强制爆款线。

经验线不触发自动撤稿、重发、修改锁稿、禁止人物/类别或更换模板；不覆盖已授权任务。当前优先固定现行模板，试验一项主要变量；超线或未达线只是下一次诊断的入口。

## 8. 预判如何与结果校准

初期不计算“实测分－编辑分”。先检查每条可检验预判是否兑现，并按编辑分项/原句特征查看实际开场、全程及可得曲线的关系，同时保留高预评低实测、低预评高实测的案例。

累计足够可比、真正事前冻结的新稿后，形成“编辑特征→预计开场/全程相对位置区间”的校准版本。评估需使用后续未参与规则形成的新作或按时间分开的留出样本；小样本只报告方向、误差与不确定性，不宣称模型已可靠。

只有预测实测分与观察实测分使用同一指标、时长范围、观察窗口和参照池时，才可比较预测误差。原始比率方向与原句预判也要复核，不能只看数字差。

禁止把真实留存先加入评分，再用同一批留存证明评分预测准确。历史复评只能描述案例，不能填成新系统的事前验证成绩。

## 9. 每篇复盘的诊断记录

使用固定顺序：
- 观察事实：原始指标、同口径分数、曲线区间或评论原话，注明缺项。
- 预判偏差：冻结时哪项判断/哪句预期未兑现。
- 候选原因：对应具体原句，分别检查兴趣、理解、承诺兑现、节奏和情绪；列出标题、首帧、画面、声音、时长、受众、流量来源和异常等替代解释。
- 下一次改法：落到一项可执行写作变化，不只写“提高信息密度”。
- 验证方法：下一批采用范围、主要变量、主指标、观察窗口、比较基准、继续/暂停/回滚条件。
- 验证结果：支持、反对或证据不足；注明实际执行偏差。

没有逐秒曲线与真实句子/画面/声音对齐，只能指出“开场或整体表现弱”和候选原因，不能宣布某一句导致跳出。即便曲线对齐，也只是定位线索，原因仍需新作对照验证。

评论用于识别具体惊讶点、理解障碍、强反方、纠错及下一期需求，不把高赞或争吵总量当留存证据；抽样范围与反例保留。

### 9.1 成功、失败与反例的三维对照

每日逐作品指标复核之外，选取有可比证据的重点作品作对照，尽量覆盖：成功、失败、观看指标较好但未放量、未越经验线却起量。不存在可比成员时写明缺口，不凑例子；作品角色与“成功/未放量”的判断条件、观察窗口应先说明，不能只挑支持当前假说的作品。

每组必须分别检查以下三个维度，按“证据→候选假说→下一次单变量动作→同龄期复核”记录；证据不足时不强写原因：

| 维度 | 必须核对的证据与问题 |
| --- | --- |
| 选题 | 熟悉人物是否便于识别，具体事件及代价是否明确，首句承诺之外是否有材料支持的后续变化；不以同一人物、同一书或“杀人”标签代替事件分析 |
| 口播 | 引用实际原句，分别看首句承诺、兑现、后半新增行动/选择/处置/证据、冷名字与制度解释的必要性；反复判词或换修辞不计作新增事实 |
| 实际制作 | 看首图是否帮助理解首句动作，关键人物关系、字幕可读性、画面顺序与新增事实是否对应；区分计划与真实执行，不能仅按使用同一模板判定制作效果相同 |

开头、选题和首图共同变化，只能提出组合假说，不把2秒跳出归因到一个词；没有逐秒曲线、真实音轨及画面对应，不声称某句或某帧造成具体掉点。完播好但播放低时继续检查传播、受众与流量来源等缺项，不自动判定文案失败。

每次校准保留高编辑分/低实测和低编辑分/高实测反例；只有真正事前冻结的稿件用于预测检验，旧作回溯分用于发现标准盲点。新稿评审额外写清“首句承诺—前半兑现—后半新增收益”，这是对现有五项的取证要求，不另加权或重算总分。

三维动作优先在后续获批新作验证，不倒改已经发布/锁稿作品。下一次复核使用预先登记的同龄期、时长与参照条件，同时记录没有控制的题材、模板、声音和曝光差异。评论补充观众需求和理解线索，不代替留人指标。

## 10. 自动调优如何执行

每日复盘自动积累偏差和案例，提出写作提示、结构建议、学习样本与评分校准的候选调整；下一次提供新口播时读取当前已生效规则及正在验证的适用试验，随稿完成预评。

采用“候选→小范围试行→独立新作验证→默认采用/暂停/回滚”的状态链：
1. 单条爆款或失败可以触发试验候选，不能直接证明一种写法普遍有效。
2. 每轮预先确定要解决的偏差，优先只改变一个主要写作变量；样本范围、指标和判断条件在看结果前记录。
3. 同题材、模板、声音同时变化只能记组合试运行，不能称严格A/B或单因素因果验证。
4. 通过多个可比新作验证，信号方向较一致、无明显未解释混杂且没有不可接受的理解/事实问题，才升级默认写作规则；证据不足保持试验状态，不为每天更新而强行改规则。
5. 自动变化限定于已授权的策划/口播评审与运营方法；不修改已锁稿、已排期作品，不自动重发、发布、生成素材或操作账号互动，不变更制作PRD。
6. 回滚保留失败版本、受影响范围和原因，不删掉反例。用户可随时调整或撤销规则。

每次实际调整记录writing_system_version、editorial_score_version、outcome_score_version、benchmark_version中哪项变了。改变一种版本不自动升级其他版本，防止把基准变化误认为写法进步。

## 11. 文字留存与存放边界

仓库保存本现行协议、[版本与原因记录](operations_script_review_history.md)、必要接续入口；不保存逐集全文、动态指标、完整评论或日报。日常明细沿用本地/授权运营工作区及飞书，完整稿件与成片只在本地。

运营工作区稳定文件名可采用“三只不服_口播评审台账.jsonl”；飞书可映射同一记录键，不另建重复任务。每条至少包括：
作品键/真实作品ID、稿件版本及本地位置、发布与评分时间、四类版本、五项编辑分及总分、原句预判、风险、实际执行核验、观察窗口、真实龄期、原始指标及缺项、参照池和有效N、两项实测分、偏差、候选原因、试验/迭代ID、下一步及验证结果。
未发布时作品ID为空而不虚构；发布后绑定内部键。每次预评、改稿、快照与迭代追加版本，不覆盖历史事实。

每次规则实质变化，将“原问题→采用证据/反例→改动→适用范围→新作验证→回滚条件”写入版本与原因记录，再更新现行协议。仓库发布以独立规范/接续维护处理，正常提交并远端读回，报告提交号；常规作品与日报更新不触发Git同步。

## 12. 接续与实施状态

新策划/运营会话读取本协议和迭代记录，并接续既有运营工作区；普通老电脑制作继续只读本地采用稿与制作规则，不新增GitHub或运营登录前置步骤。

本次协议升级本身只确认文字规则；仓库发布、既有定时任务提示接入、飞书适配、工作区台账与真实采集运行分别记录状态，不能以文档提交代替自动化已启用或已跑通。接入时更新既有任务和稳定文件，不重复创建日程，也不在PRD添加本评分系统或数字经验线。叙事/制作执行规则由独立PRD维护，不等于本系统已完成运行验证。
